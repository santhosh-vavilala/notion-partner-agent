Detailed repository walkthrough

A governed AI bridge to Notion

The application turns natural-language requests into controlled Notion operations. The model understands and proposes; normal application code routes, approves, executes, and validates.

FastAPILangGraphOpenAI ResponsesMCPOAuth 2.0Pydantic

1. The mental model

This is a coordinator around an LLM, not a model with unrestricted workspace access. Fuzzy language understanding and deterministic control are deliberately separated.

OpenAI

Brain

Classifies intent, selects from real tools, and turns raw results into a readable answer.

LangGraph

Traffic controller

Owns state transitions, branching, checkpointing, limits, and the approval stop.

Notion MCP

Hands

Advertises live capabilities and performs actual reads or writes under OAuth.

Central design ideaThe LLM may propose an action, but it never directly calls Notion. Code filters its proposal against discovered tools, limits calls, checks write approval, and only then invokes MCP.

Validate

Pydantic bounds message and ID lengths and defaults write approval to false.

Create context

The service generates a trace UUID and uses thread_id as the LangGraph checkpoint key.

Classify

A strict structured model call returns intent, partner, risk, objective, and whether Notion is needed.

Discover and plan

Notion supplies its live catalog. The model chooses calls; code removes unknown names and applies the configured limit.

Govern

Write-looking tools stop before execution unless the request explicitly carries approval.

Execute, re-plan, and ground

Calls run sequentially and results are normalized. The planner receives prior calls/results and may choose the next dependent step—such as access check → search → fetch—until it returns no calls or reaches the total call limit; then the final model call explains the accumulated results.

4. Three execution paths

General

“Hello”

classify → general → END

No Notion connection is made.

Read

“Find the policy”

classify → discover → (plan → gate → execute) × bounded rounds → synthesize

Write

“Create a page”

First run stops at approval. Approval resubmits with approve_write:true, so classification and planning happen again before execution.

8. Concepts behind it

Agent vs chatbot

A chatbot maps text to text. This agent maps text through a state machine that discovers abilities, pauses for consent, causes side effects, and returns evidence.

Structured outputs

JSON Schema restricts model shape; Pydantic validates it. Probabilistic interpretation becomes data that ordinary code can branch on.

MCP

A standard handshake plus tools/list and tools/call lets the client plan against live partner capabilities.

OAuth + PKCE

The operator authorizes without giving a password. Authorization code and verifier yield renewable scoped tokens.

Human in the loop

A potential side effect stops at a control point. Consent is explicit input, never inferred from model confidence.

Defense in depth

The prompt prohibits writes on reads, the gate detects writes, and execution checks risk again.

Grounding

Workspace answers are generated after retrieval with MCP results included in the final model request.

Async I/O

async/await lets the server handle other work while OpenAI, Notion, or HTTP is waiting.

10. Important limitations

Security

Single operator

user_id is metadata, not credential selection. Multi-user deployment needs authentication and encrypted per-user storage.

Policy

Name heuristic

Replace substrings with an allowlist carrying explicit risk, scopes, and argument policy.

Planning

Bounded re-planning

Dependent actions now work across rounds, but all rounds share max_mcp_tool_calls. Complex tasks that need more steps stop at the cap and synthesize from partial results.

Memory

No chat history

Checkpointed state exists, but model prompts receive only the current message. Add a message reducer and bounded history.

Reliability

Ambiguous retries

A timeout may happen after a write commits. Add idempotency/reconciliation and durable audit records.

Persistence

In memory only

DATABASE_URL is unused. Replicas need database checkpoints.

Errors

Details exposed

Sanitize public 502 messages and log detail under the trace ID.

Container

Read-only secrets

Compose mounts secrets read-only while token refresh may rewrite them. Use writable secure/external storage.

Debugging order

  1. Check /v1/status.
  2. Inspect response trace, intent, calls, and results.
  3. Routing issue: inspect classify; wrong action: plan_tools; access issue: OAuth/MCP.
  4. For writes, verify both route risk and is_write_tool.
